| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Injection | ticcmd arguments (position values from config) | medium | mitigate | ArmConfig values from system.json are validated by ConfigLoader deserialization to int; position values default 1500/0 (safe range for Pololu Tic). No user input reaches ticcmd — only config-driven constants. Still, validate position >= 0 in ArmController before passing to subprocess. |
| T-04-02 | Tampering | state.txt manipulated by external process (MonitorAppweb) | medium | mitigate | StateManager.SetArmState uses File.WriteAllText which is atomic for small files on NTFS. If MonitorAppweb writes concurrently, last-writer-wins is acceptable — both apps agree on arm=1 = open, arm=0 = closed (per existing contract). Detect and log conflicts at next read. |
| T-04-03 | Spoofing | ticcmd binary not from Pololu (PATH injection) | low | accept | Ticcmd must be in system PATH by design — this is a deployment requirement documented in project setup. An attacker who can modify PATH already has local system access. Phase 5 deployment will verify ticcmd availability before first use. |
| T-04-04 | Denial of Service | ticcmd subprocess fails repeatedly (device disconnected) | high | mitigate | Each RunTicCmd call is bounded by the subprocess lifecycle — no unbounded waits. After deenergize completes, next iteration re-attempts from current state. Add a per-iteration arm command timeout guard in Wave 2 if needed. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy gate + blocking human checkpoint for [ASSUMED]/[SUS] |
