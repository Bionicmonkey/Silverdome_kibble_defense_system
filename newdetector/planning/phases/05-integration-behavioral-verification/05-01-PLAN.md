The current bug is in Program.cs line 152 where SaveEventFile receives a mixed string:

Current: `EventManager.SaveEventFile($"Detected {firstAnimal} {DateTime.Now:yyyyMMdd_HH_mm_ss}")`
This produces filename: "20240101_120000 Detected cat 20240101_120000.txt" — wrong format.

The issue is that the notation parameter serves dual purpose (filename type + content). MonitorAppweb expects arm events with specific filename patterns: "Arm Closed.txt" or "Arm Opened.txt". Animal detection events can keep their current naming since they're only for human review.

Fix approach:
1. In Program.cs, replace line 152's SaveEventFile call for arm actions with two dedicated calls:
   - For close action: `EventManager.SaveEventFile("Arm Closed")` → produces "{timestamp} Arm Closed.txt"
   - For open action: `EventManager.SaveEventFile("Arm Opened")` → produces "{timestamp} Arm Opened.txt"

2. Remove line 152 entirely (the "Detected cat..." notation text file) since it's not produced by the reference detector and doesn't match its convention.

3. Update arm control calls in Program.cs: Where ArmController.OpenAsync() is called (lines 104, 134), add a call to `EventManager.SaveEventFile("Arm Opened")` after the arm action succeeds. Where ArmController.CloseAsync() is called (lines 111, 120), add `EventManager.SaveEventFile("Arm Closed")`.

4. SaveEventJpg for animal types continues unchanged — "cat", "opossum", "ferret", "dog" are correct filenames matching reference detector's SaveEventImageCopy convention: "{timestamp} {animal}.jpg".

5. No changes needed to EventManager.SaveEventFile itself — the naming logic is correct; only the callers need updating.
